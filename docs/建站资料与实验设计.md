# LabFlow：建站资料与实验设计

这份资料只选了和当前项目有关的做法：怎样省掉反复上传文件的麻烦，怎样把耗材记录做清楚，以及怎样用小实验检查网站是否好用。下面分别标明官方功能、个别使用者的反馈和我们准备验证的设想。它们不代表我们做过问卷，也不能直接当作实验结果。

## 1. 建站先把更新流程理顺

开发者 Pseudoyu 在个人博客里记录过自己的选择：从维护服务器，逐步转向把源码放进 Git 仓库，再自动构建和发布。对他来说，省下来的不只是上传文件的时间，每次改动也有记录，回头查问题更方便。这是作者的第一手经历；文章初版较早，后来也更新过方案，其中旧套餐和免费额度不适合作为现在的承诺。参见[作者的建站记录](https://www.pseudoyu.com/zh/2022/03/24/free_blog_deploy_using_hugo_and_cusdis)。

我们可以借鉴这套工作方法：你负责合并代码，同学把发现的问题记在仓库里；确认修改通过检查后，再提交到发布分支。Cloudflare 的[官方 Git 集成说明](https://developers.cloudflare.com/pages/get-started/git-integration/)支持连接 GitHub 或 GitLab，随后按代码推送自动构建、部署。

对 LabFlow 来说，现成的网页可以先托管出去。共享库存和服务端账号还要另外接入，不能因为网页能打开，就把多人协作写成已经完成。每轮最好只解决一个明确问题，例如“换台电脑也能看到同一份库存”，做完再增加别的功能。

## 2. 同类项目里，哪些内容值得借鉴

### 耗材领用和设备借还要分清

**官方项目功能：** Snipe-IT 将资产、配件、组件和耗材分开处理。它的耗材指会被使用掉的物品，发给具体的人后，不按设备的方式办理归还。说明见[官方概念介绍](https://snipe-it.readme.io/docs/overview)。

这和我们的题目很接近。手套、吸头、滤纸可以记录领取数量和用途；仪器预约、维修、归还属于另一套业务，现阶段不用一起塞进来。以后若需要处理未使用耗材退回，也应单独规定退回条件和记录方式，不能直接删掉原领用单。

### 库存变化要能查到原因

**官方项目功能：** InvenTree 的库存历史记录操作人、时间及数量或位置变化，增减库存、盘点等操作有相应记录。参见[库存追踪](https://docs.inventree.org/en/stable/stock/tracking/)和[库存调整](https://docs.inventree.org/en/latest/stock/adjust/)。

我们借鉴的是这个思路：看到剩余数量时，还能继续查到它怎么算出来。发生盘点差异，应留下调整数量、原因和操作人；不要只把总数改成一个新数字，否则后续核对很难解释。

### 找到名称以后，还得找到实物

**个别使用者的公开反馈：** eLabFTW 的一位微生物实验室使用者提出，搜索能够找到资源，但预览里看不到存放位置，需要逐条打开详情。他希望直接显示位置，也不想把同一个位置维护在两个地方。这是一个具体使用者的需求，不能写成普遍调查结论。原讨论见[Issue #6775](https://github.com/elabftw/elabftw/issues/6775)。

对我们而言，一个实用的改进是让库存列表直接显示“实验室、柜号、层位”。先验证这样是否少点几次、少找一会儿，再决定是否加入更复杂的库位结构。eLabFTW 也有[从 CSV 导入资源的官方说明](https://doc.elabftw.net/docs/6.0/usage/import-export/)，以后迁移现有表格时可以参考它对列名、空行和重复字段的处理要求。

## 3. 五个可以实际做的实验

**以下均是建议方案，尚未作为本次实验执行。** 表中的预期行为是验收条件，执行后还要填写实际结果。你负责准备可重复的版本和数据，同学按步骤操作、记时间和错误；条件允许时交换一次角色。

| 实验 | 怎样做 | 记录什么、怎样判断 |
| --- | --- | --- |
| 查找点击次数 | 准备两种界面：位置放在详情页、位置直接放在列表。用数量相同、难度相近的查找任务比较，交换两种界面的测试顺序。 | 记录完成时间、点击次数、是否找错。说明参加人数和任务数量；两个人的小样本只能反映这次测试。 |
| 库存边界 | 每次都恢复为库存 5，再分别领用 4、5、6，避免上一次扣减影响下一次。 | 前两次应成功，剩余分别为 1 和 0；领用 6 应失败，库存仍为 5，并且没有新增成功流水。 |
| 重复提交 | 用同一个业务单号发送两次相同领用请求；再用新单号提交一笔新的合法领用。 | 第一组只能扣一次、保留一笔业务流水；第二组应作为新业务处理。记录返回信息和库存，不能只看按钮是否禁用。 |
| 两人并发领用 | 初始库存为 5，两个独立账号用不同业务单号同时申请领用 4。 | 最多一笔成功，最终库存为 1；另一笔明确失败。检查成功流水数量，不能出现负库存。 |
| 角色权限 | 普通成员调用管理员操作，并尝试查询不属于自己的领用记录；管理员再执行允许的操作。 | 记录接口响应、可见数据和数据库变化。受限操作必须由服务端拒绝，隐藏按钮本身不算验证通过。 |

每次保留版本号、测试环境、初始数据、操作步骤、预期结果、实际结果和证据。失败也照实记录，修复后用同样条件复测。报告的重点可以放在“为什么会错、改了哪里、复测说明了什么”，不用凑成功率或编造用户评价。

## 4. 可用在网站上的原创文案

下面是根据本项目重新写的文案建议，并非引用网友原话。

**首页标题**

还剩多少，放在哪儿，谁领走了。

**首页介绍**

实验前先查一下耗材够不够。新到的耗材登记入库，领走时留一条记录，剩余数量会随操作更新。想核对某一次领用，可以按时间或领用人查流水。

**当前演示版说明**

这一版可以先试完整流程。数据保存在当前浏览器里，换台电脑不会自动同步。下一步会接入共享数据库，让两个人看到同一份库存。

**使用指南说明**

选好耗材，填上数量和用途，再提交领用记录。如果数量超过库存，系统会提示你修改。提交后到流水里检查一下，确认这一笔记对了。
