# LabFlow v0.3：云端初始化与多人验收

## 当前状态

- **已写好且通过隔离自动测试**：D1 表结构、入库领用原子更新、账号管理、会话、服务端权限、业务编号去重、库存核对，以及工作台成员管理页面。
- **尚需线上确认**：Cloudflare 最新部署、自动创建的 D1 `DB` 绑定、真实首次初始化、不同浏览器真实登录、八个页面实际点击与截图。
- 本轮真实浏览器自动化因当前测试环境返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，没有绕过环境限制。另以虚拟 DOM 做过11组渲染烟测。**不能把渲染烟测写成浏览器点击成功**。

## 部署设置与首个管理员

Worker 项目：`git-project-for-the-web-design-exam`。GitHub `main` 分支直接触发 Cloudflare Workers Builds，部署命令 `npx wrangler deploy`。根目录 `wrangler.toml` 中 `main="src/worker.mjs"`，`assets.directory="./dist"`，`d1_databases` 的绑定名为 `DB`。

1. 在 Cloudflare → Workers & Pages → 本项目 → Deployments 确认最新构建为 `Ready`，展开 Build 日志检查 D1 是否成功自动建立。
2. 在 Worker 的 Bindings/Overview 检查是否有 `DB`（D1）。如果没有，先在 Cloudflare → Storage & databases → D1 创建数据库，然后在 Worker Bindings 绑定为 `DB`；注意 Github 同步时应保持 `wrangler.toml` 与实际绑定一致。
3. 在 Settings → Variables and Secrets 添加 **Secret**（不是纯文本变量）`ADMIN_SETUP_TOKEN`，自己生成安全随机凭证，不少于24字符，自己保存。任何人都不应将密码或该凭证发到 ChatGPT、公开仓库、截图或调研问卷。
4. 访问已启用的 `workers.dev` 网址，在 `app.html` 的首次管理员页面输入账号、密码及初始化凭证。管理员密码至少12字符。只允许成功初始化一次。
5. 新建正式成员账号；管理员将初始密码单独交给本人，成员登录后自行修改。Cloudflare 云端版本没有预设 admin/Member123! 演示账户。

如显示 `DATABASE_NOT_BOUND`：检查 D1 绑定名称是否为 `DB`；显示 `SETUP_TOKEN_MISSING`：检查 Cloudflare Secret 是否设置并在最新版本可用；显示 500：到 Cloudflare Logs 查看具体数据库错误，不要直接清空数据库。

## 按角色分工

成员A负责 Worker/D1 数据层、权限和业务规则、修复与部署记录。成员B负责账号和八个页面的实际验收、截图、问题记录，参与跨设备测试。两人共同签认库存是否一致，把真实测试结果写入实验报告。自动化测试可以引用源码中的 `tests/`，问卷与真实用户访谈另按实际收集。

## 未做的功能与限制

没有自助注册、邮箱验证、找回密码、批量导入、D1 自动备份与正式审计日志；需要管理员重设成员密码。云端数据不会从离线演示或本地 SQLite 自动迁移。用户账号与 D1 数据表为本次云端新建；本版只做一处库存点、按整数单位处理。上线后应审核 Cloudflare 免费额度和访问策略，使用合成数据进行课程测试。
