# LabFlow 网站迭代计划

## 目标与推进方式

把现有课设工作台逐步完善为可以持续使用的独立网站。每一轮只完成一组明确目标，留下可运行版本、检查记录和下一轮问题清单，再继续推进。

本计划按依赖顺序安排工作，不设未经两人确认的截止日期，也不创建自动任务。云服务、正式账号、自有域名等需要实际选定和配置后，才能记为完成。

## 当前基线：v0.2 网站基础版

现有程序已实现八个相互联动的功能：耗材档案、入库登记、领用登记、库存查询、出入库流水、低库存预警、库存核对和统计。它们共享同一套数据，属于同一个实验室耗材管理系统。

本轮网站基础将首页、使用指南、下载中心和工作台分开，统一页面导航。使用指南说明示例账号、五分钟演示和数据保存方式；下载中心提供源码 ZIP、单文件离线 HTML 和运行说明三个入口。

### 当前数据边界

浏览器演示把数据保存在当前浏览器、当前站点的 IndexedDB；离线 HTML 也属于浏览器演示。本机 Python 版把数据保存在 `data/lab.db`，由服务端检查身份和权限。三者不会自动互相同步。

目前公开的管理员和成员账号仅用于课程演示。下一轮的“真实账号”需要独立的服务端身份流程，不能把浏览器模拟角色当作正式账号系统。

## 下一轮优先：共享数据与真实账号

**状态：待开展。** 下一轮先让两位组员能够从不同浏览器登录，同看一套已保存的数据。保留现有库存、幂等、权限和核对规则，避免同时重做大量页面。

| 具体工作 | 交付内容 | 谁主做 |
| --- | --- | --- |
| 明确试用范围 | 哪个实验室、哪些耗材、谁可登记、谁只查本人记录 | B 整理，A 确认技术影响 |
| 选择最小可用的云端存储与运行方式 | 选型说明、环境配置和可重复启动步骤 | A |
| 接入共享业务数据 | 两台设备读到同一套耗材与流水；错误处理仍清晰 | A |
| 建立真实账号与服务端权限 | 管理员和成员身份、登录退出、会话失效与操作授权 | A；B 复核使用流程 |
| 完成一次小范围试用 | 实际操作记录、截图、问题清单及修复复核 | B；A 修复与整合 |

### 这一轮怎样算完成

- 两台设备使用不同身份登录，管理员登记一笔入库后，另一台刷新能看到同一笔已提交的数据。
- 成员只能取得本人领用记录；直接请求管理接口同样会被服务端拒绝。
- 同一业务单号重试只记一次，两个并发领用请求不能把库存扣成负数。
- 退出或会话失效后，受保护的操作需要重新登录。
- 关闭页面、重新打开后，已提交业务数据仍存在；出错时不切换到另一份演示数据。
- 关键页面完成实际点击检查，记录结果与遗留问题。只有真实执行过的检查才标为通过。

账号开通先服务于明确的试用成员。是否开放自助注册、如何找回账号、是否需要更多角色，先由 B 收集需求，再决定后续范围。

## 后续一：成员管理

**状态：待规划。** 共享数据与真实账号稳定后，再补充管理员维护成员的页面，包括创建或邀请成员、停用身份、查看角色和处理账号问题。

停用账号后应保留历史领用归属；角色变化不能改变已入账记录。B 先整理实际需要的管理动作，A 实现最小的一组功能，两人共同检查不同身份的操作结果。

## 后续二：备份与操作日志

**状态：待规划。** 先明确需要保留哪些数据、谁能备份、如何恢复，再增加可执行的备份与恢复流程。导出 CSV 继续作为查阅材料，不能称为已经具备完整恢复能力。

操作日志优先记录档案调整、下限变更、启用停用和管理操作，让两人能追溯“谁在何时改了什么”。库存业务流水继续保留原始记录，不以日志功能替代入库和领用记录。

这一阶段的验收要包含一次隔离环境中的真实恢复演练，并检查恢复后的历史汇总与当前库存是否一致。

## 后续三：部署维护与可选自有域名

**状态：待规划。** 下一轮共享试用需要最小可用的云端部署；这里进一步完善日常发布、环境配置、运行状态检查和回退步骤，减少升级时对已有数据的影响。

自有域名是可选项。网站功能、共享数据和运行方式稳定后，再决定是否购买或绑定域名、配置 HTTPS 和正式访问地址。没有实际配置前，不把平台预览地址称为已拥有自有域名，也不预先记录部署成功。

## 两人分工与每轮交接

| 人员 | 稳定职责 | 每轮应交出的材料 |
| --- | --- | --- |
| 成员 A（主负责人） | 技术整合、数据与权限实现、问题修复、版本打包 | 可运行版本、改动说明、运行方式、自动化结果和已知限制 |
| 成员 B | 需求调查、管理员规则核实、页面操作验证和反馈整理 | 真实需求记录、验收用例、操作截图、问题单与复核结论 |
| 两人共同 | 确定范围、检查结果、更新课设报告和准备演示 | 本轮完成项、未完成项、下一轮最多三项优先任务 |

每轮交接先演示一条完整业务流程，再确认问题清单。A 解释数据如何保存和校验，B 解释需求依据以及测试是否真正执行。AI 可以继续协助起草、编码和检查，两人的真实调查与判断仍需由本人完成。

## 建议先走的完整流程

新建启用耗材，单位为“包”、下限为 5；入库 20，给成员 A 领用 15，确认库存 5 时仍预警；再入库 2，确认库存 7 且解除预警；核对全部历史，确认 22 − 15 = 7、差额为 0；最后用成员 A 和成员 B 分别登录，检查记录可见范围。

这条流程的数字是演示输入与预期结果。实际操作之后，再把观察到的结果、截图和问题写入检查记录。
