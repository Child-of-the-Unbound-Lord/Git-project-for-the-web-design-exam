# LabFlow 实验室耗材管理网站 · v0.2

这是从软件工程课程作品逐步完善的网站。本轮 v0.2 增加独立首页、使用指南、下载中心和统一工作台入口；原有八个功能页面共享耗材与流水数据，覆盖报告中的三个核心模块。

线上版本用于当前浏览器内的业务体验；下载后的完整本地版使用 Python 服务端和 SQLite 数据库。云端共享数据、真实账号和成员管理列入下一阶段，尚未作为本轮已完成功能。

## 先运行

### 完整本地版（用于课程演示与运行验证）

需要 Python 3.10 或更高版本，不需要安装第三方 Python 包。

- Windows：解压整个文件夹后，双击 `start_windows.bat`。
- macOS/Linux：在项目文件夹打开终端，执行 `bash start_macos_linux.sh`。
- 通用命令：`python3 server.py`；Windows 也可用 `py -3 server.py`。

启动后访问终端显示的地址，默认是 `http://127.0.0.1:8000`，从网站首页点击“进入工作台”。停止时在终端按 Ctrl+C。首次运行会建立演示数据库；以后启动保留已有数据。数据库在 `data/lab.db`，关闭程序后可以复制该文件备份。

正常启动还会生成下载中心的三个文件。生成过程只打包程序源文件与演示夹具，排除运行数据库、会话数据、Git元数据和托管配置；生成失败会明确报错，不把失败写成已完成。

### 浏览器演示版

在线页面与完整本地版使用同一套界面。在线演示在当前浏览器的 IndexedDB 中保存数据，不会把业务数据同步到其他设备。浏览器演示中的角色切换用于展示权限差异，完整服务端鉴权由本地 Python 版本提供。

下载中心的 `LabFlow_v0.2_offline.html` 和源码包中的 `直接打开_八个小程序.html` 已包含工作台的全部页面资源，可以直接双击试用；`打开小程序.html` 则使用 `web/app.html` 中的源文件。若浏览器限制本地文件的 IndexedDB，请使用上面的 Python 启动方式。页面会明确标记当前运行模式，不会把不可用的存储假装成已保存。

## 八个可操作的小程序

| 入口 | 可以实际做什么 | 报告对应 |
| --- | --- | --- |
| 耗材档案 | 新增耗材、维护规格与位置、设置下限、启用与停用 | FR02，基础数据 |
| 入库登记 | 选择耗材，登记数量与备注，生成入库流水 | M01 / FR03 |
| 领用登记 | 指定领用人，检查库存并登记领用 | M01 / FR04 |
| 库存查询 | 搜索名称与编码，查看数量、单位、位置和状态 | M02 / FR05 |
| 出入库流水 | 按耗材、类型、日期筛选记录；成员只查本人 | M02 / FR06 |
| 低库存预警 | 查看低于或等于下限的耗材，调整下限并刷新 | M03 / FR07、FR08 |
| 库存核对 | 汇总全部历史流水，比较当前库存并显示差额 | M02 / FR06 |
| 统计看板 | 根据已有数据计算库存与领用统计，导出可见记录 | M02 的展示扩展 |

`web/` 中还准备了八个对应的 HTML 入口。它们进入同一个系统的不同功能页，数据会联动；这是一套完整作品中的八个小程序模块。

## 五分钟演示路线

1. 用管理员登录。介绍总览与八个入口，说明当前为演示数据。
2. 在“耗材档案”中新增 `DEMO-01`，名称“演示连接线”，单位“包”，下限 `5`。初始库存应为 `0`。
3. 在“入库登记”中给它入库 `20` 包。到库存查询中确认当前库存 `20`。
4. 在“领用登记”中为成员 A 领用 `15` 包。库存应为 `5`，并出现在预警列表中，说明“等于下限也预警”。
5. 再尝试领用 `6` 包，观察库存不足提示；库存仍应为 `5`，流水中不应出现这笔失败记录。
6. 入库 `2` 包。库存变为 `7`，预警解除。
7. 打开流水查看实际业务单号，执行库存核对，确认 `20 - 15 + 2 = 7`、差额为 `0`。
8. 退出后用成员 A 登录，查看本人领用记录；说明管理功能在完整本地版还会受到服务端检查。

不要为了演示反复重置已录入的有用数据。页面提供的“恢复演示数据”会要求确认；执行后会替换当前模式的数据集。

## 两人怎么分工

| 人员 | 负责解释、修改和交付的部分 |
| --- | --- |
| 成员 A（你，主负责人） | 整体结构、耗材档案、入库、领用、库存查询与核对；整合代码和报告，完成主要演示 |
| 成员 B | 问卷和管理员访谈；复核流水、预警和统计页面；根据用例复现结果，整理运行截图和问题记录 |
| 两人共同 | 核对需求是否符合真实场景；熟悉自己负责的输入、处理、输出及异常；完成最终提交 |

AI 已协助生成代码、界面、规则实现与自动化检查。每位成员仍需能够解释自己负责的模块。问卷回答和访谈记录应使用实际收集的内容。

## 设计要点

- 新耗材库存从零开始，所有数量变化都留下流水。
- 数量必须是正整数，下限必须是非负整数，库存不会扣成负数。
- 完整本地版在一个 SQLite 事务中同时更新库存和新增流水，失败一起回滚。
- 同一业务单号和相同内容重试不重复入账；同一单号改成不同内容会报冲突。
- 已入账流水不可直接编辑或删除；停用耗材保留历史，但不允许新增出入库，也不进入预警列表。
- 核对始终使用全部历史，界面的日期筛选只影响流水展示。
- 本地版管理员权限由服务端验证，成员只能取得本人领用记录。
